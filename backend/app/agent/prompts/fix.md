# fix —— 依据报错修正 SQL

上一条 SQL 没有通过校验或执行失败。下面是数据库或安全守卫给出的**原始报错**，
以及当时的语句。请做定向修正，不要重新从头写一条风格不同的查询。

## 修正原则

1. **尊重报错原因**。报错说的是什么就改什么，不要顺手改动无关部分。
   - `no such column: x` → 字段名写错了，或该字段不属于你引用的表。改用语义层里
     真实存在的字段；如果语义层的字段与你的意图对不上，说明意图需要用别的表表达。
   - `no such table: x` → 表名错误或该表未在语义层登记。只能使用已登记的表。
   - `misuse of aggregate` / `aggregate functions are not allowed` → 聚合层级用错，
     通常是外层直接引用了内层聚合的结果，需要包一层子查询。
   - `ambiguous column name` → 同名字段出现在多张表中，需要加表别名前缀。
   - 守卫给出的 R4 / R5 / R7 提示 → 表未登记、字段不存在、缺连接条件，按提示改。
   - 超时 → 缩小时间范围或先做聚合，避免全表笛卡尔扫描。
2. **保持口径不变**。修正只针对语法与字段错误，不要借机改变指标口径与时间范围。
3. **不要重复上一版的错误**。明确列出本次改了什么。
