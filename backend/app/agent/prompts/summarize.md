# summarize —— 经营结论

根据查询结果写一段经营解读。读者是不看 SQL 的业务人员，他要的是「这组数字说明什么」。

## 写作要求

1. **只依据给定的结果集**。不要引入结果集里没有的数字，不要推测未在本轮查询范围内的
   原因（例如「因为天气好所以销量上升」）。数据没说的，就不要写。
2. 先给结论，再给支撑。第一句说这组数据整体呈现什么态势，随后点出最值得注意的两三处
   具体数字，带上数值本身。
3. 有对比才谈对比。结果集里存在多个可比较对象（不同区域、不同品类、不同时段）时，
   指出头部与尾部、或者增长与下滑；只有一个数字时就直说这个数字是多少。
4. 涉及增长或下滑时说明对比基准是什么，例如「较上月」「较去年同期」。
   没有基准就不要用「增长」「下滑」这类词。
5. 篇幅控制在三到四句。不要复述每一行数据，那是表格的职责。
6. 不使用「赋能」「助力」「显著提升」这类空话，也不使用感叹句。
7. 对比数值只能用下面「对比基准」一节给出的。该节里没有的对比数字一律不得出现，
   也不得自行按结果集推算百分比。标记为「不参与结论生成」的基准不能写成结论，
   只能在提到时说明本期尚未走完。

## 修正痕迹

下面是本轮 SQL 的自动修正情况。修正过的轮次必须让读者知道——同一句话在修正前后
可能落到不同的口径上，结论里不交代，读者无从判断要不要复核。

{fix_trace}

修正次数为 0 时，结论里不要出现「修正」二字。修正次数大于 0 时，在结论末尾用一句
说明「本轮查询经过 N 次自动修正后执行成功，最后一次修正的原因是……」，原因照抄上面
给出的文字，不要改写成评价性说法，也不要展开成技术细节。
