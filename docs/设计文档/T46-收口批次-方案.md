## T46.1　时间词锚点修正

### 起因

`pytest -q`（LLM_MOCK=true）当前 **2 failed / 544 passed**。两条失败均出自 `test_slot_coverage.py`：

```
expected 统计区间为上个月（2026-09-01 起至 2026-09-30 止）
detail    语句实际统计 2026-08-01 至 2026-08-31
```

`FULL_SQL` 写的是 `created_at >= '2026-08-01' AND created_at < '2026-09-01'`，对应「上个月 = 2026-08」（按数据截止 2026-09-22 的上一个自然月）。`validate.py:117` 与 `retrieve.py:27` 调用 `check_slot_coverage` / `recall` 时均未传 `today`，回退到 `dt.date.today() = 2026-10-16`，得到 2026-09。

T44 已知边界写的「周期完整性用系统日期而非数据截止日判定」实际覆盖面比 partial_period 更广：所有相对时间词换算都从系统日期出发。

### 现状证据

| 位置 | 调用 | `today` 走向 |
|---|---|---|
| `loader.py:625` | `ref = today or dt.date.today()` | 默认系统日期 |
| `loader.py:746` | `recall(..., today=None)` | 接受但默认 None |
| `retrieve.py:27` | `recall(question, catalog)` | **未传** |
| `validate.py:117` | `check_slot_coverage(..., catalog=catalog)` | **未传** |
| `slot_coverage.py:443` | `resolve_time_term(matched, today)` | 接受但默认 None |

`resolve_time_term` 与 `check_slot_coverage` 在签名层已经预留了 `today` 参数，是设计时留的扩展点；调用链没把它接上才是根因。

### 方案 A（推荐）：按数据截止日锚定

| 步骤 | 改动文件 | 内容 |
|---|---|---|
| 1 | `app/db/repository.py` | 暴露 `data_as_of`：`min(orders.paid_at_max, refunds.created_at_max)` 截断到日 |
| 2 | `app/main.py` | 启动时把 `data_as_of` 注入到 graph 装配 |
| 3 | `app/agent/graph.py` | 把 `data_as_of` 作为节点依赖注入到 retrieve / validate |
| 4 | `app/agent/nodes/retrieve.py:27` | `recall(question, catalog, today=data_as_of)` |
| 5 | `app/agent/nodes/validate.py:117` | `check_slot_coverage(..., today=data_as_of)` |
| 6 | `backend/tests/conftest.py` | 加 session-scope `data_as_of` fixture，注入到测试 |
| 7 | `backend/eval/run_eval.py` | `--today` 默认值改为读 `data_as_of` |

风险：6 处改动跨装配层、节点层、测试层。要保证 real-model 与 mock-model 行为一致。

### 方案 B：测试侧固定 today

不动生产代码，把 `today` 钉在 conftest 的 `data_as_of` fixture 里。

| 维度 | A | B |
|---|---|---|
| 改动量 | 6 处 | 1 处 |
| 根因是否修 | 是 | 否（生产仍按系统日期换算） |
| 真实模型下 | 自动一致 | 仍按系统日期，会重新暴露 |

### 验收口径

- `pytest -q`（LLM_MOCK=true）：**544 passed / 0 failed**（当前 2 failed）
- `pytest -q`（LLM_MOCK=false + 有效 key）：全部通过
- 端到端：当前日期 2026-10-16、数据截止 2026-10-14（重 seed 后）时，问「上个月华东销量」返回 2026-09-01~2026-09-30 区间，与 `/api/health` 的 `data_as_of` 一致

### 已知边界

- partial_period 判定仍由 `baselines.py` 内部按 ref 算，本节未一并接入 `data_as_of`
- 数据陈旧后 `data_as_of` 滞后于真实系统日期，slot_coverage 仍按滞后的 `data_as_of` 算
