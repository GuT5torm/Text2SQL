## 三、本轮修复的缺陷

除上一轮已记录的两处（`AgentState` 未声明字段、`ROUND()` 包裹的聚合识别不到）外，本轮又定位并修了三处。三处的共同点是都不抛异常，只表现为「基准莫名缺失」或「数字不对」。

**一、注入时间谓词时未包 `exp.Where`。** `tree.set("where", 条件表达式)` 传入的必须是 `exp.Where` 节点，直接塞条件时 sqlglot 不报错，生成的 SQL 却把条件并进 JOIN 的 `ON` 子句：`ON r.order_id = o.id` 后面直接接 `created_at >= '...'`，渲染成 `o.idcreated_at >= '...'`。执行阶段报「no such column」，而排查时看到的只有「本期聚合查询失败」。

**二、注入的时间列不带表别名。** `orders` 与 `refunds` 都有 `created_at`，任何带 `LEFT JOIN refunds` 的语句注入裸 `created_at` 都会撞上 ambiguous column。改为取 FROM 的第一个表作限定符（`o.created_at`）。附带修掉一处隐性错误：sqlglot 的 `Select` 用 `from_` 存 FROM 子句（同一棵树里 `group` 却不带下划线），原写法 `args["from"]` 恒为 `None`，别名退化成裸列名。

**三、本期与对比期用了两套算法。** 本期是「外层 `SUM()` 包住分组结果」，对比期是「去掉 GROUP BY 重算」。加法型指标两者相同，比率型指标完全不同：退款率本期算成各区比率之和 0.348，环比期算成整体比率 0.051，偏离度失真约 6 倍。现统一为「去掉 GROUP BY 后执行同一条语句」，并按聚合别名取值（避免维度列本身是数值时取错列）。同时补上前置判定：SELECT 里没有聚合函数时整组基准不给，不再凑一个明细行的值。

**四、闰日平移抛异常。** `_last_year_window` 直接 `dt.date(year - 1, 2, 29)` 会抛 `ValueError`。改为 `_shift_years`，2-29 在非闰年回落到 2-28。

## 十、三条判定规则的口径

判定全部由服务端确定性规则完成，不经过模型。规则写进 `finding_rules.yaml`，指标只写差异项，未写的从 `default` 继承。

| 规则 | 判据 | 基线取法 | 默认阈值 |
|---|---|---|---|
| deviation | 与对比基准的相对偏离 | mom.value，环比不可比时退回 yoy | ±20% |
| rank | 同维度内排名处于前后各若干比例，且与中位水平偏离超过阈值 | 同维度中位数 | 前后各 20%，最少 4 个切片 |
| absolute | 绝对值越过配置阈值 | 阈值本身写进 baseline 字段 | 按指标配，当前仅退款率 > 10% 一档 |

严重度两级：达到阈值 2 倍升「关注」，绝对阈值默认直接给「关注」。同一（维度, 切片）只保留一条，比较顺序为严重度 → 规则种类（业务阈值优先于统计排名）→ 偏离绝对值。

**不完整周期不参与 deviation 判定。** 判定只读 `baselines` 里的 `comparable` 标记，不自己判断周期——两处各判一次会判出不同结论。「今年以来各区域的退款率」只产出排名类标记，不产出偏离类标记，评测用例 `drill-l002` 用 `findings_absent: [deviation, absolute]` 把这条固化下来。

**取值列与维度列的选择。** 指标列优先按列名与主指标同名，否则取最右侧的数值列；维度列优先取第一个非数值列，全是数值时（按月份分组得到 202605）取第一个非指标列。选错列不会报错，只会让标记指向错误的切片，因此两条都写了用例。

## 十一、下钻的两个触发点

| 触发点 | 问句 | 是否加深 |
|---|---|---|
| finding（异常标记） | `{时间}{切片}的{指标}按{下一层维度}分布` | 加深一层 |
| cell（结果表单元格） | `{时间}{切片}的{指标}` | 只过滤，不加深 |

下一层维度取自指标在 `metrics.yaml` 里声明的 `dimensions` 顺序，跳过时间类维度（`order_date` / `order_month` / `order_quarter`）——它们已由 `time_range` 承担。顺序写在配置而不是代码里，是为了避免「配置说有这个维度、代码却跳过了它」。

维度写法归一兼容三种输入：配置名 `region`、显示名 `销售大区`、结果表列别名 `大区`。第三种最容易被忽略——findings 里的 `dimension` 取的是结果集列名，而列名来自 SQL 的 `AS`，写的是口语简称。

**接口只返回问句，不执行查询。** 下钻的本质是槽位继承，产出是「下一句该怎么问」；执行仍走 `/api/chat` 的既有链路，同一套守卫、超时与落库。接口直接跑链路会绕过前端对 SSE 进度的处理，也会让「下钻轮次与普通轮次一样落库」变成两套写入路径。

**FR-L-5 的构造数据用例放在单测。** 评测集跑的是 `data/ecommerce.db`，写入「一个订单两笔退款」会污染演示数据；构造数据只有临时库能干净验证。该用例断言同一原因分组内两种口径就分出差别（质量问题：按笔 3 vs 按单 2），不需要跨原因求和才看得出来。两种计数表达式**能在真实库上执行**这一层仍用 `business_repo` 夹具在单测里验证。

### 缺口一：图表侧未标注「本期未完整」（FR-M-2）

FR-M-2 的原文要求是「未走完的周期在**结果与图表上**标注」。结果侧已由 `MetricBadge` 承担，图表侧未做：`ChartPanel` 的 `Props` 里没有 `partialPeriod`，后端 `app/chart/` 模块内也没有任何 `partial` 相关处理（已 grep 确认）。`AnswerCard` 调用 `ChartPanel` 时只传了 `chart` / `columns` / `rows` / `title` / `exportPrefix`。

后果是：本轮若为不完整周期（如「本月」「今年以来」），口径标签上写着「本期未完整」，正下方的柱状图没有任何提示。使用者看图时读到的是「本月只有这么高」。这与 FR-M-2 的判定说明「只有 FR-D-2 时使用者仍会去比」是同一类问题，只是从时间范围挪到了图表。

未修，是因为本轮任务是核查与记录，改动需先确认。

### 缺口二：第三批缺验收文档

`docs/设计文档/` 下有第 1、2、3 步的验收概览，第三批的验收内容目前只散在本文件第十六、十七节，没有单独的验收卡片。

### 缺口三：历史回看不返回 `partial_period` 与 `granularity`

`app/api/session.py` 的轮次映射返回了 `findings` 与 `baselines`，未返回 `partial_period` 与 `granularity`。前端 `useChatStream` 读取 `turn.partial_period` 与 `turn.granularity`，取到 `undefined` 后分别降级为 `false` 与 `null`。因为 `MetricBadge` 优先读 `baselines.partial_period`，而 `baselines` 确实随回看返回，所以界面表现正确，属于「字段契约不齐但结果不错」。`granularity` 目前界面上无消费点。

### 缺口四：返回体的 `baselines.rule` 未进前端类型

`baselines` 实测含 `rule` 键（取值来自 `baseline_rules.yaml` 的命中项），`frontend/src/api/types.ts` 的 `Baselines` 未声明。TypeScript 结构化类型不会因此报错，但该字段属事实存在而未登记。

### 核查中发现的既有问题：展示结果未按召回的时间范围过滤

「上个月各区域的成交总额」实测：

| 来源 | 数值 |
|---|---|
| `time_range` | 2026-08-01 至 2026-09-01（标签「上个月」） |
| 实际执行的 SQL | `WHERE o.status NOT IN ('cancelled','pending')`，**无任何时间谓词** |
| 结果表各大区求和 | 58,695,892.05（全量口径） |
| `baselines.current_value` | 2,917,532.33（因 `compute_baselines` 自行注入了 8 月窗口） |

原因是桩实现的 `_MOCK_SQL_BY_KEYWORD` 四套模板都不带时间谓词（`app/llm/gateway.py` 的模板串里没有任何 `created_at` 条件）。真实模型接入后由 `generate` 产出带时间条件的语句，该现象消失。

需要留意的是：界面当前同时呈现「上个月」标签、全量口径的结果表、以及按 8 月窗口算出的基准，三者对不上，而没有任何提示。这正是 FR-D-5（时间范围一致核对）要拦的情形，属第 7 批范围。在桩模式下演示时，不要把结果表的绝对值当作「上个月」的数字引用。
