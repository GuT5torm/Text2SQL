# PRD — 产品需求规格说明书

> 项目：基于 Text2SQL 的电商数据分析 Agent　｜　版本：v1.0.0
> 定位：课程作业 / 毕设演示　｜　运行形态：本地单机，单用户
> 上游：《Text2SQL-Agent-系统架构设计.md》

---

## 一、背景与问题

### 1.1 业务现状

电商经营分析中，业务人员需要看一个临时数据时的典型路径是：向数据团队提出需求、等待排期、拿到报表。一个简单问题从提出到拿到结果，通常需要半天到一天。对于「上个季度华东区各品类的成交总额」这类明确且一次性的问题，这条链路的等待时间远超问题本身的价值。

### 1.2 现有方案的局限

| 方案 | 能做到 | 局限 |
|---|---|---|
| 固定报表平台 | 覆盖常规指标，数据准确 | 维度组合固定，临时问题排期长 |
| 自助 BI 工具 | 拖拽式取数 | 需要理解表结构与指标定义，业务人员上手成本高 |
| 直接把表结构交给大模型 | 自然语言提问，零门槛 | 口径靠模型猜测，结果不可复现；可能编造字段；存在破坏性语句风险 |

### 1.3 本项目的切入点

保留自然语言提问的低门槛，同时用两处工程手段消除第三类方案的两个问题：

1. 口径从猜测改为配置。业务词的聚合口径写成显式的 YAML 配置，生成 SQL 前先召回，模型只在给定口径内组合，不自行定义。
2. 执行前做 AST 级校验。所有语句经安全守卫校验后才允许在只读连接上执行。

## 二、目标用户与场景

| 角色 | 特征 | 使用场景 |
|---|---|---|
| 业务运营 | 不看 SQL，只看结论与图表 | 临时取数、周报数据、活动复盘 |
| 数据分析师 | 看得懂 SQL，关注口径 | 验证口径、快速探查 |
| 答辩评审 / 课程学习者 | 关注架构与实现 | 评审链路完整性、复现实训 |

演示场景以业务运营为主，因此「口径可见」与「结论可读」是必须项，不是加分项。

## 三、功能需求

优先级采用 MoSCoW 标注。M 为本版必须交付，S 为应当交付，C 为可选。

### 3.1 对话取数（M）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| F1-1 | 用户输入自然语言问题，系统返回结果与图表 | 浏览器内完成一次完整问答 |
| F1-2 | 支持多轮追问，能处理「那上个月呢」这类省略主语的问法 | 连续三问，后两问能继承上文主体与指标 |
| F1-3 | 信息不足时反问，而非猜测后给出错误结果 | 「销售额怎么样」触发反问，且反问给出具体选项 |
| F1-4 | 等待期间显示当前所处阶段 | 问答过程中至少看到四个阶段提示 |
| F1-5 | 非取数问题（问候、致谢）给出可用问法示例，不调用数据库 | 输入「你好」返回示例问法 |

### 3.2 SQL 展示与口径标注（M）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| F2-1 | 每轮回答下方展示实际执行的 SQL，默认折叠 | 展开后可见完整语句 |
| F2-2 | 标注本轮采用的指标口径与边界说明 | 结果与 `metrics.yaml` 中对应口径一致 |
| F2-3 | 安全校验拦截时展示具体拦截原因 | 构造违规语句，前端能看到规则编号与原因 |
| F2-4 | 修正重试过程可见 | 构造失败场景，能看到重试次数与每次改动说明 |

### 3.3 图表与分析结论（M）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| F3-1 | 结果集自动匹配图表类型 | 时间维度得折线、单维度对比得柱状、占比得饼图 |
| F3-2 | 模型输出的图表配置在渲染前做字段校验；后端校验不通过退回规则决策，规则决策仍不可用或结果集为空时以表格呈现 | 构造引用不存在字段的配置，不出现空白图表 |
| F3-3 | 生成经营结论，注明口径与数据范围 | 结论中不出现结果集以外的数字 |
| F3-4 | 结果集以表格呈现，支持查看全部列 | 宽表场景下表格可读 |

**图表类型决策规则**（F3-1 的判定依据，由后端 `visualize` 节点执行）

| 结果集特征 | 图表类型 |
|---|---|
| 维度为时间且行数大于 3 | 折线 |
| 单个维度对比且行数不超过 30 | 柱状 |
| 问占比构成，单度量且维度取值不超过 12 个 | 饼图 |
| 列数超过 4，或无数值度量，或维度组合复杂 | 表格 |

补充规则：结果只有一行一列时用表格；行数超过 30 的柱状图改折线或表格。图型只有折线、柱状、饼图、表格四类，不做数字卡。

决策顺序为模型输出优先、规则兜底：模型给出的字段若不在结果集列名中，后端校验不通过则退回规则决策（F3-2）；前端渲染前再做一次字段存在性校验，不通过则退回表格。

### 3.4 历史会话（S）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| F4-1 | 保存历次问答，含问题、结论、语句与结果集快照 | 重启后列表仍在 |
| F4-2 | 支持关键词搜索 | 按问题关键词能检索到历史记录 |
| F4-3 | 支持查看、删除、归档 | 操作后列表同步更新 |

### 3.5 评测集（M）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| F5-1 | 维护评测集，每条含问题与验证方式 | 评测集覆盖七个指标与主要维度 |
| F5-2 | 一键跑出可执行率与准确率基线 | 脚本输出汇总结果 |

## 四、数据范围

### 4.1 表结构

六张表，粒度与用途如下：

| 表 | 粒度 | 用途 |
|---|---|---|
| `users` | 一行一个用户 | 用户等级、城市等属性维度 |
| `categories` | 一行一个品类 | 品类层级 |
| `products` | 一行一个商品 | 商品属性、品牌 |
| `orders` | 一行一个订单 | 订单主表，含状态、渠道、区域、下单时间 |
| `order_items` | 一行一个订单中的一个商品 | 金额与数量的明细来源 |
| `refunds` | 一行一条退款记录 | 退款率计算 |

时间字段统一存 ISO8601 字符串，日期筛选使用 SQLite 的 `strftime` 与 `date` 函数。SQLite 没有 `quarter()` 函数，季度维度用表达式 `CAST((CAST(strftime('%m', 下单时间) AS INTEGER) + 2) / 3 AS INTEGER)` 计算；该表达式预置在 `tables.yaml` 的维度定义中随元数据一起注入 Prompt，不由模型自行构造。

### 4.2 指标口径

七个指标，口径与边界说明在 `semantic/metrics.yaml` 中显式定义：

| 指标 | 显示名 | 口径要点 | 边界说明 |
|---|---|---|---|
| `gmv` | 成交总额 | 订单明细金额合计 | 不含已取消订单；不扣退款 |
| `sales_volume` | 销量 | 商品件数合计 | 默认件数口径，订单数口径需明确说明 |
| `order_count` | 订单量 | 订单去重计数 | 受状态筛选影响 |
| `aov` | 客单价 | 成交总额 / 订单数 | 按订单数口径，非按用户数 |
| `refund_rate` | 退款率 | 退款订单数 / 订单数 | 以订单数为分母，非金额口径 |
| `paying_users` | 付费用户数 | 成交用户去重计数 | 与注册用户数不同口径 |
| `gross_profit` | 毛利 | 成交额减成本 | 成本取 `products.cost_price`，为当前成本而非下单时点成本，跨期对比时需注意；不含履约与推广费用 |

### 4.3 可用维度

九个维度：下单日期、下单月份、下单季度、区域、渠道、品类、品牌、用户等级、城市。

## 五、非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | 只允许单条 SELECT；表与字段走白名单；只读连接；强制 LIMIT；执行超时中断 |
| 性能 | 单条查询 10 秒内返回，超出中断并说明；结果集上限 1000 行 |
| 可复现 | 样例库由固定随机种子生成，同一环境重复生成结果一致 |
| 可观测 | 每轮返回节点耗时；网关记录调用次数与 token 用量 |
| 可移植 | 密钥只出现在 `.env`；依赖版本锁定；不依赖本机特有配置 |
| 透明 | 任何数字都能追溯到具体语句与具体口径 |

---

## 六、明确不做的事

本版不实现的范围，写在这里是为了避免评审时被当成遗漏：

- 不做用户体系与鉴权，本地单用户使用；
- 不做写入类功能，系统对业务库只读。会话记录、评测记录等运行时数据写入独立的会话库文件，不与业务库共用连接；
- 不做向量检索，语义层召回采用规则匹配；
- 不做多数据源接入，只连一个 SQLite 业务库；
- 不做查询缓存与异步任务队列；
- 不做容器化与编排，按本地进程方式启动。

## 七、验收标准

| 项 | 标准 |
|---|---|
| 链路完整性 | 八个业务节点与三个终态节点全部生效，重试回环在构造的失败场景中可触发 |
| 查询安全 | 安全守卫的单元测试全部通过，守卫七条规则逐条有用例覆盖；语句超时中断在仓储层单独有用例覆盖 |
| 口径一致 | 评测集中的指标类问题，返回口径与 `metrics.yaml` 定义一致 |
| 准确率 | 评测集首次运行结果作为基线记录在案 |
| 可复现 | 在干净环境中按 README 步骤可启动并完成一次问答 |
| 透明展示 | 每轮回答都能看到实际语句与本轮口径 |
