### 与方案的两处偏差（已在 CHANGELOG T46 节记录）

1. 锚点公式用 `created_at` 而非方案写的 `paid_at`：全部 SQL 的时间谓词写在 `orders.created_at` 上，按 `paid_at` 锚定会在跨月订单上让「上个月」落到查不到数据的月份；`/api/health` 原口径也是 `created_at`，同公式才能保证验收要求的「问出来的区间与 health 报的截止日一致」。
2. `partial_period` 判定一并接入锚点（方案列为已知边界）：不接的话数据月份一过「本月」就被判成完整周期，eval 的 `base-m002` 当天即变红——同一缺陷的另一处显形，没有理由留到下一批。
