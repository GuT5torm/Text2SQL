# UI/UX — 界面设计文档

> 项目：基于 Text2SQL 的电商数据分析 Agent　｜　版本：v1.0.0
> 技术栈：React 18 + TypeScript + Vite + Ant Design + ECharts
> 上游：《PRD-产品需求规格说明书.md》《Text2SQL-Agent-系统架构设计.md》第 8 节

---

## 一、设计目标

| 目标 | 说明 | 衡量方式 |
|---|---|---|
| 等待可感知 | 一次问答要数秒到十几秒，用户必须知道系统在做什么 | 全过程无「看起来卡住」的状态 |
| 结果可追溯 | 任何数字都能看到它来自哪条语句、哪个口径 | SQL 与口径在两跳之内可达 |
| 失败可理解 | 拦截与报错给出原因，不出现空白结果 | 失败态有明确文案与下一步建议 |
| 界面不喧宾夺主 | 数据、图表、结论是主体 | 主色调中性，图表配色区分度足够 |

## 二、信息架构

```
ChatPage（主页面）
├── 顶部栏            会话标题 / 新建会话 / 历史入口
├── 左侧：对话区
│   ├── 消息流        用户提问气泡 + 助手回答卡片
│   └── 输入框        自适应高度，Enter 发送，Shift+Enter 换行
└── 右侧：结果区
    ├── 结论卡片      经营解读 + 亮点 + 口径说明
    ├── 图表区        ECharts 容器，高度固定 320px
    ├── SQL 面板      Collapse，默认折叠
    └── 结果表格      可横向滚动，行数多时分页

HistoryPage（历史会话）
├── 搜索框            按问题关键词过滤
├── 状态筛选          全部 / 未归档 / 已归档
└── 会话列表          标题、时间、轮次、操作（查看 / 归档 / 删除）
```

归档为软删除：归档后的会话不再出现在默认列表中，可通过状态筛选找回，不物理删除记录。

## 三、布局规范

### 3.1 主页面

三区布局，左侧对话区为固定宽度、右侧结果区自适应。以 1100px 窗口为基准时对话区约占 38%。

| 区域 | 宽度 | 说明 |
|---|---|---|
| 对话区 | 默认 420px，可拖拽调整，范围 320–560px | 拖拽边界即上下限 |
| 结果区 | 自适应 | 最小 640px |
| 间距 | 区域间距 16px，卡片间距 12px | Ant Design 基础间距体系 |

窗口宽度小于 1024px 时改为上下堆叠，对话区在上、结果区在下，各自占满宽度。

### 3.2 助手回答卡片

一轮回答的固定结构，顺序不可调换：

```
┌────────────────────────────────────────┐
│ 阶段指示（完成后收起为一行）              │
├────────────────────────────────────────┤
│ 结论文本                                │
│ · 亮点 1                                │
│ · 亮点 2                                │
├────────────────────────────────────────┤
│ [口径标签] 成交总额  [口径标签] 不含取消单  │
├────────────────────────────────────────┤
│ 图表区                                  │
├────────────────────────────────────────┤
│ ▸ 查看执行的 SQL（1）                    │
├────────────────────────────────────────┤
│ 结果表格                                │
└────────────────────────────────────────┘
```

## 四、组件清单

| 组件 | 职责 | 关键约束 |
|---|---|---|
| `StageIndicator` | 按 SSE 事件显示节点进度 | 事件来自 `stage`，按到达顺序追加、不重排；`stages` 的作用域是单轮问答，发起新一轮时清空后重新累积 |
| `ChatPanel` | 输入与消息流 | 发送后禁用输入直到收到 `result` 或 `error` |
| `ChartPanel` | ECharts 封装 | 渲染前校验字段存在于结果集列，否则退回表格 |
| `SqlPanel` | SQL 折叠展示 | 展示实际执行的语句；存在改写时同时展示改写前语句 |
| `ResultTable` | 结果集表格 | 超过 50 行分页；列名直接取结果集列名；单次下发上限由守卫的 LIMIT 强制为 1000 行，宽表以横向滚动分页呈现，不引入虚拟滚动 |
| `MetricBadge` | 本轮口径标签 | 内容取自返回的 `metric_used` 与 `caveats` |
| `useChatStream` | SSE 接收 Hook | 解析 `stage` / `result` / `error` / `done`，`done` 时关闭连接 |

## 五、交互与状态设计

### 5.1 问答主流程

| 步骤 | 界面表现 |
|---|---|
| 用户提交 | 输入框禁用，出现用户气泡 |
| 收到 `stage` | 阶段指示追加一条，显示标签与耗时 |
| 收到 `result` | 渲染结论、口径标签、图表、SQL 面板、表格 |
| 收到 `error` | 展示错误文案，保留已收到的阶段记录 |
| 收到 `done` | 关闭连接，输入框恢复可用 |

### 5.2 阶段文案

后端推送的节点名与前端展示文案的对应关系：

| 节点 | 展示文案 |
|---|---|
| `route` | 正在理解问题 |
| `retrieve` | 正在匹配指标口径 |
| `generate` | 正在生成查询 |
| `validate` | 正在校验查询安全性 |
| `execute` | 正在执行查询 |
| `fix` | 正在依据报错修正查询 |
| `visualize` | 正在选择图表 |
| `summarize` | 正在分析结果 |
| `respond` | 已给出回答 |
| `clarify` | 需要补充信息 |
| `give_up` | 未能生成可执行查询 |

共十一个节点：八个业务节点加上述三个终态节点。终态节点同样推送 `stage` 事件，因此阶段列表中会出现 `respond` / `clarify` / `give_up` 之一。

### 5.3 异常态

| 状态 | 表现 | 引导 |
|---|---|---|
| SQL 被拦截 | 黄色提示条，展示规则编号与原因 | 建议换更具体的问法 |
| 重试中 | 阶段指示中出现 `fix`，标注第几次修正 | 无需干预 |
| 重试耗尽 | 红色提示，展示最后一次语句与报错 | 建议缩小范围或补充口径 |
| 结果为空 | 蓝色提示，说明可能原因 | 建议放宽时间范围 |
| 反问（`status = clarify`） | 灰色提示条，列出需要补充的信息与可选项 | 点选可选项或重新表述问题 |
| 闲聊（`status = chitchat`） | 常规回答气泡，附可用问法示例 | 从示例中选一个继续提问 |
| 网络中断 | 顶部全局提示 | 提供重试按钮 |

## 六、视觉规范

### 6.1 配色

| 用途 | 取值 | 说明 |
|---|---|---|
| 主色 | `#1677FF` | 沿用 Ant Design 默认主色 |
| 成功 | `#52C41A` | 阶段完成、查询成功 |
| 警告 | `#FAAD14` | 校验拦截、结果为空 |
| 错误 | `#FF4D4F` | 重试耗尽、请求失败 |
| 文本主色 | `rgba(0,0,0,0.88)` | 正文 |
| 文本次色 | `rgba(0,0,0,0.45)` | 时间、辅助说明 |
| 图表序列色 | 10 色循环 | 分类数据区分度足够，相邻色不重复 |

金额与涨跌不使用红绿语义色。本项目是经营数据分析，不是行情看板，避免与股票涨跌的配色惯例混淆。

### 6.2 字体与圆角

| 项 | 取值 |
|---|---|
| 正文字号 | 14px，行高 1.6 |
| 结论文本 | 15px，行高 1.75 |
| 代码字号 | 13px，等宽字体 |
| 圆角 | 卡片 8px，标签 4px，输入框 6px |

### 6.3 图表规范

| 项 | 规则 |
|---|---|
| 高度 | 固定 320px，不随内容变化 |
| 标题 | 由后端给出，不显示在图表内，用卡片标题呈现 |
| 图例 | 序列数大于 1 时显示，置于底部 |
| 坐标轴标签 | 过长时截断为 8 个字符加省略号，悬浮显示全称 |
| 数值格式 | 金额显示千分位与两位小数；比率显示百分比 |
| 空数据 | 不渲染图表，改为表格呈现 |
| 图型来源 | 图型由后端在 `chart.chart_type` 中给出，前端不重新决策业务图型。决策规则见 PRD 3.3 的图表类型决策规则表 |

## 八、与后端的契约

前端不做任何业务判断，只做展示与字段校验。以下字段由后端返回，前端直接消费：

| 字段 | 用途 |
|---|---|
| `stages[]` | 阶段指示的数据源。每项含 `node` / `label` / `status`（`running` / `done` / `failed`）/ `duration_ms` / `detail`。作用域为**单轮问答**，每轮重新累积，不跨轮叠加 |
| `answer` / `insight` / `highlights` | 结论卡片 |
| `metric_used` / `caveats` / `time_range` | 口径标签 |
| `chart.chart_type` / `chart.option` | 图表渲染，渲染前校验字段 |
| `sql` / `original_sql` | SQL 面板。`sql` 为实际执行语句，可能已被行数上限包裹改写；`original_sql` 为模型生成的原始语句，人工核对时用这一条 |
| `columns` / `rows` / `row_count` / `truncated` | 结果表格。`row_count` 是本轮下发的行数；`truncated` 为 `true` 表示结果已被行数上限截断，`row_count` 不等于真实命中行数 |
| `guard.rule_id` / `guard.reason` | 拦截提示条，展示被命中的规则编号与原因 |
| `attempts` | 生成尝试次数（整数）；每次修正的改动说明取自 `stages[].detail` |
| `status` | 决定展示哪一类终态。取值为 `ok` / `clarify` / `chitchat` / `error`，分别对应成功态、反问态、闲聊态、失败态 |
| `archived` | 历史会话是否已归档 |
