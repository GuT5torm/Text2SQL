## 一、任务拆解原则

三条原则支配下面的拆解顺序：

1. **按依赖排序，不按模块排序**。同一模块的工作可能被拆到不同阶段，例如 `db/` 的守卫在数据访问层阶段完成，而 `db/` 的会话存储在后端阶段补。
2. **每一步都有可独立验证的产出**。做完一步就能运行一次，看到结果，而不是攒到最后联调。
3. **最早暴露最大的不确定性**。项目最大的不确定性是「模型能不能稳定产出可执行 SQL」，因此三节点链路要尽早跑通。

| 编号 | 任务 | 依赖 | 产出 | 验收 |
|---|---|---|---|---|
| T1.1 | 编写建表语句 `data/schema.sql` | 无 | 六表 + 索引 | 可在 SQLite 中执行 |
| T1.2 | 编写造数脚本 `data/seed.py` | T1.1 | 可复现样例库 | 固定种子重复生成结果一致 |
| T1.3 | 编写表结构元数据 `semantic/tables.yaml` | T1.1 | 六表字段元数据 + 九个维度 | 字段名与库内实际一致 |
| T1.4 | 编写指标口径库 `semantic/metrics.yaml` | T1.3 | 七个指标定义 | 口径能对应到真实字段 |
| T1.5 | 编写同义词配置 `semantic/synonyms.yaml` | T1.3 | 同义词、枚举值口语、相对时间词 | 常见问法可命中 |
| T1.6 | 实现加载与召回 `semantic/loader.py` | T1.3–T1.5 | 配置校验 + 规则召回 | 一致性校验接口返回 `consistent: true` |

阶段出口：命令行执行语义层一致性校验返回 `consistent: true`，且规则召回能命中典型问题。此时还没有接入层，不做接口验收；`GET /api/semantic/health` 的验收放在阶段五 T5.4。

### 阶段二：数据访问层与安全沙箱（实践 1 学时）

| 编号 | 任务 | 依赖 | 产出 | 验收 |
|---|---|---|---|---|
| T2.1 | 只读引擎与连接加固 `db/engine.py` | T1.2 | 只读连接 | 写操作被拒绝 |
| T2.2 | Repository 抽象 `db/repository.py` | 无 | 接口定义 | 无 SQLite 专属类型泄漏 |
| T2.3 | SQLite 实现 `db/sqlite_repo.py` | T2.1 T2.2 | 查询执行（业务库只读连接）+ 会话存储（独立会话库读写连接） | 业务库连接上的写操作被拒绝；会话能正常读写；超时与行数上限生效 |
| T2.4 | SQL 安全守卫 `db/guard.py` | T1.3 | 守卫七条规则校验 | 单测全绿，逐条规则有用例 |

说明：语句超时中断由 T2.3 仓储层的 progress handler 实现，不属于守卫的拦截规则，两个功能的测试用例分别归属 T2.3 与 T2.4。

阶段出口：守卫七条规则的单元测试全部通过，语句超时中断在仓储层有独立用例覆盖。

## 三、依赖关系

```
T1.1 → T1.2 ─┬─→ T2.1 → T2.3 ─┐
      T1.3 ──┼─→ T1.6 ────────┼─→ T3.3 → T4.2 → T4.4 → T5.1 → T5.2
      T1.4 ──┤                 │
      T1.5 ──┘                 ├─→ T2.4
                               │
      T3.1 → T3.2 ─────────────┘
                               └─→ T4.3 → T4.4 → T4.6
                                              └→ T5.5 → T5.6 → T5.7
                                                            └→ T6.1 → T6.2
```

关键路径：`T1.1 → T1.2 → T2.1 → T2.3 → T3.3 → T4.3 → T4.4 → T5.1 → T5.2 → T5.5 → T5.6 → T5.7`。

T4.4 的前置有 T4.2 与 T4.3 两条，二者可以并行，关键路径取其中较长的一条（经 T4.3）；T5.6 的前置 T5.2 与 T5.5 同理，T5.5 不依赖后端，但必须排在 T5.6 之前。

可以并行的部分：语义层三份 YAML（T1.3–T1.5）之间无依赖；前端工程初始化（T5.5）不依赖后端任何任务，可在阶段二就开始。

## 五、交付标准

| 类别 | 标准 |
|---|---|
| 代码 | 三条分层硬约束全部满足；`requirements.txt` 锁定版本；`.env.example` 不含真实密钥 |
| 测试 | 守卫规则单测覆盖七条，语句超时中断在仓储层有独立用例；语义层加载与召回有用例；接口有冒烟用例 |
| 文档 | 六类资源数量与《项目结构与交付规范》第九节一致 |
| 可复现 | 干净环境按 README 步骤可启动并完成一次问答 |
| 数据真实 | PPT 与文档中的演示截图取自真实运行结果，评测数字取自 `run_eval.py` 输出 |

## 七、风险与对策

| 风险 | 影响 | 对策 | 责任任务 |
|---|---|---|---|
| 模型产出 SQL 不稳定 | 演示效果不可控 | 语义层注入口径、失败修正回环、评测集回归 | T4.3 T6.1 |
| 未拿到密钥则无法验证 | 链路无法跑通 | 网关内置桩实现，无密钥也能走完整链路 | T3.2 |
| 前端与后端字段不一致 | 图表空白、展示错位 | 类型定义与 Pydantic 模型对齐，图表渲染前校验字段 | T5.7 |
| Nginx 缓冲导致 SSE 失效 | 进度一次性吐出 | 部署配置关闭缓冲并延长超时 | T6.4 |
| 依赖版本漂移 | 环境重建失败 | 锁定版本并记录实测组合 | T6.3 |
