# 08 — 前端开发实训语料库

## 前端在本项目中的定位

前端只做三件事：展示、收集输入、校验渲染所需的字段。它不做任何业务判断——图表类型由后端决定，口径由后端给出，是否反问由后端决定。

这一定位来自架构设计的分层约束。它的好处是前端逻辑简单、可测试；代价是任何业务规则变更都要改后端，前端无法自行兜底。

## 类型定义

类型文件与后端返回逐项对应，是联调阶段减少低错误的第一步。需要覆盖：

| 类型 | 对应内容 |
|---|---|
| `StageEvent` | 节点名、展示标签、状态（`running` / `done` / `failed`）、详情、耗时 |
| `ChartPayload` | 图表类型、配置对象、理由、警告、表格列与行 |
| `ChatResult` | 状态、结论、亮点、语句、口径、列、行、阶段列表 |
| `Session` | 会话 ID、标题、创建与更新时间、归档标记 |

类型定义写完以后，与后端返回做一次逐字段核对。字段名不一致（例如后端是 `row_count` 而前端写成 `rowsCount`）是最常见的联调问题。

## SSE Hook 设计

`useChatStream` 是整个前端的核心，职责为：发起请求、解析四类事件、维护状态、关闭连接。

需要处理的要点：

**请求方式。** 对话接口是 POST，需要携带请求体，浏览器原生的 `EventSource` 不支持，也不会自动带上自定义请求头。用 `fetch` 配合 `ReadableStream` 自行解析，或引入 SSE 客户端库。浏览器端 axios 基于 XHR，拿不到流式响应，不能用于这条链路。

**事件解析。** SSE 帧由 `event:` 与 `data:` 两行构成，`data` 是单行 JSON。解析时按空行切分帧，再按行取事件名与数据。

**状态维护。** 阶段事件按到达顺序追加，不重排；结果事件到达时替换结果；错误事件到达时记录错误。

**连接关闭。** 收到 `done` 时关闭，异常时也要关闭。关闭逻辑放在最后统一执行，避免异常分支泄漏连接。组件卸载时同样要关闭。

**输入禁用。** 发送后禁用输入框，直到收到结果、错误或流结束，避免重复提交。

常见的两个缺陷：只在成功分支关闭连接，异常时泄漏；按事件类型重建阶段列表而不是追加，导致顺序错乱。

## ECharts 封装与字段校验

图表组件接收后端给出的配置，但**渲染前必须校验字段**。

原因是模型输出的字段映射可能引用结果集中不存在的列。直接渲染会得到一张空白图，用户无法判断是没数据还是画错了，这类问题在演示时很难当场解释。

校验规则：

1. 取出配置中引用的字段名；
2. 与结果集的列名比对；
3. 全部存在则渲染图表，否则退回表格并给出提示。

其他要点：容器固定高度（高度为 0 是空白图最常见的原因之一）；空数据不渲染图表；坐标轴标签过长时截断加省略号；金额显示千分位与两位小数。

## 组件职责与约束

| 组件 | 职责 | 关键约束 |
|---|---|---|
| `StageIndicator` | 显示节点进度 | 按到达顺序追加，完成后收起为一行；阶段列表按轮次独立存放，每轮显示的就是服务端返回的 `stages`，不需要手动清空 |
| `ChatPanel` | 输入与消息流 | 发送后禁用输入直到本轮结束 |
| `ChartPanel` | 图表渲染 | 渲染前校验字段，不通过退回表格 |
| `SqlPanel` | SQL 折叠展示 | 展示实际执行的语句，有改写时同时展示改写前语句 |
| `ResultTable` | 结果集表格 | 超过 50 行分页，列名取自结果集 |
| `MetricBadge` | 口径标签 | 内容取自返回的指标与边界说明 |

## 状态管理

本项目状态规模不大，不需要引入专门的状态库。采用的组织方式：

| 状态 | 位置 |
|---|---|
| 阶段列表与当前结果 | `useChatStream` 内部 |
| 会话列表 | `useSessions` 内部 |
| 页面级共享（当前会话 ID） | `ChatPage` 状态，向下传递 |

判断是否需要状态库的依据是有没有跨多层的共享状态。本项目中会话 ID 只在两层之间传递，提升到页面级即可。

## 开发顺序建议

1. 初始化工程并配置代理，确认开发服务器可启动；
2. 定义类型，与后端返回逐字段核对；
3. 实现 SSE Hook，用命令行工具先验证后端事件流正确；
4. 实现对话页与阶段指示，确认等待期间能看到进度；
5. 实现图表组件与字段校验，构造错误配置验证兜底；
6. 实现 SQL 面板、结果表格与口径标签；
7. 实现历史会话页。

第 3 步单独验证很重要。后端事件流如果本身有问题（例如被代理缓冲），在前端调试会浪费大量时间。

## AI 共创时的注意点

让 AI 写组件时，贴一段真实的后端响应 JSON。只描述字段名，AI 会自行假设结构，接上真实接口才发现对不上。

审查时搜索组件中的判断逻辑：出现的判断应该只与展示形态有关（是否截断、是否分页、是否退回表格）。出现与业务口径有关的判断，说明职责越界。
