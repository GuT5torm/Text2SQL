# 11 — 核心功能模块实现语料库

## 模块总览

四个功能模块，每个模块横跨前后端：

| 模块 | 后端承担 | 前端承担 |
|---|---|---|
| 对话取数 | 意图识别、多轮记忆、流式推送 | 输入、消息流、阶段指示 |
| SQL 展示与口径标注 | 语句改写记录、口径标签数据 | 折叠面板、口径标签 |
| 图表与分析结论 | 图表类型决策、配置生成、结论生成 | 图表渲染、字段校验、结论卡片 |
| 历史会话 | 会话与问答记录存储 | 列表、搜索、操作 |

## 对话取数

### 一次问答的完整过程

```
用户输入
  → route       意图识别：取数 / 闲聊 / 信息不足
  → retrieve    语义召回：指标口径、表结构、时间范围
  → generate    生成 SQL
  → validate    安全校验
  → execute     只读执行
  → visualize   图表决策
  → summarize   经营结论
  → 返回结果
```

校验或执行失败时进入 `fix`，修正后回到 `validate` 重新校验。

### 意图识别

三类意图：

| 意图 | 触发条件 | 后续 |
|---|---|---|
| `query` | 有指标词或范围词，或是上一轮取数问题的追问 | 进入召回与生成 |
| `chitchat` | 问候、致谢等与数据无关的内容 | 直接返回可用问法示例，不调用数据库 |
| `clarify` | 信息不足，换个理解会得到完全不同结果 | 返回反问，等用户补充 |

反问的判定要克制。只有「换个理解就会得出不同结果」时才反问，能把问题合理解释成一种明确口径时直接判 `query`。滥用反问比漏用更影响体验。

### 多轮与指代消解

「那上个月呢」这类省略主语的追问，在 `route` 节点补全为完整问题后写入状态，后续节点直接使用补全后的问法。

历史对话注入两个节点：`route` 用于判断意图与补全指代，`generate` 用于生成 SQL。注入的轮数由配置控制，默认最近六轮。

多轮记忆由 Checkpointer 以会话 ID 为键持久化。

### 流式进度

后端在每个节点完成时推送一条 `stage` 事件，前端按到达顺序追加显示。

节点名到展示文案的映射覆盖十一个节点（八个业务节点加 `respond`、`clarify` 与 `give_up`）。终态节点同样推送 `stage` 事件，前端不需要为终态单独写一套展示逻辑。完成后阶段列表收起为一行。

阶段列表的作用域是**单轮**，跨轮累积的阶段条目属于缺陷，不是预期行为。这份单轮限定由状态归约层保证：`stages` 使用自定义归约器 `merge_stages`，入口节点 `route` 出现在本次更新中即判定为新轮并丢弃历史值，因此用户发出新问题时不需要在前端清空上一轮阶段，直接按本轮到达的事件追加即可。一轮内阶段条数不固定：触发重试时会出现多条 `fix` 与 `validate`，命中闲聊时只有 `route` 与 `chitchat` 两步。

## SQL 展示与口径标注

### 展示哪一条语句

后端返回两个字段：实际执行的语句，与守卫改写前的原始语句。

前端默认展示实际执行的那条，因为它是真正跑在库上的语句；改写前的语句保留用于回溯，能看到模型原本写了什么、守卫改了什么。

R6 强制 LIMIT 是唯一的自动改写规则，它用外层包裹的方式实现，不改语义。

### 口径标签

每轮回答标注本轮采用的指标与边界说明，数据来自语义层召回结果。

例如问成交总额时，标签显示「成交总额」与「不含已取消订单；不扣退款」。这一步把不可见的假设变成可见的说明。

### 拦截与重试的呈现

校验拦截时展示具体的规则编号与原因，而不是「查询失败」。

重试过程可见：阶段指示中会出现修正条目，并标明是第几次修正。重试耗尽时展示最后一次的语句与报错，并给出下一步建议。

## 图表与分析结论

### 图表决策的两条路径

以模型输出为主、规则兜底：

1. `visualize` 节点让模型输出图表类型与字段映射；
2. 规则模块依据结果集结构（维度数、度量数、行数）生成兜底配置。

模型给出的字段若不在结果集列名中，校验不通过则退回规则决策。这样模型出错时仍能产出可渲染的图表。

### 决策规则

| 结果集特征 | 图表类型 |
|---|---|
| 横轴是时间且行数大于 3 | 折线 |
| 单个维度对比且行数不超过 30 | 柱状 |
| 问占比构成，单度量且维度取值不超过 12 个 | 饼图 |
| 列数超过 4，或无数值度量，或维度组合复杂 | 表格 |

补充规则：结果只有一行一列时用表格，单独一个数画成图没有意义；行数超过 30 的柱状图难以阅读，改折线或表格。

### 前端渲染前的字段校验

拿到配置后，前端核对配置引用的字段是否存在于结果集列名中，不通过则退回表格。

这一条不能省。模型输出的字段映射可能引用不存在的列，直接渲染会得到空白图，用户无法判断是没数据还是画错了。

### 结论生成

结论只依据本轮结果集，不引入结果集以外的数字，不推测未在本轮查询范围内的原因。

结论结构为：先给结论，再给支撑，最后列出本轮口径边界。篇幅控制在三到四句，不复述每一行数据。

## 历史会话

### 存储内容

每次问答记录包含：会话 ID、问题、结论、语句、口径信息、图表配置、结果集快照、行数、耗时、状态与错误信息。

结果集快照与当轮实际交付给前端的行数一致，落库时不做二次截断。行数量级由守卫的 LIMIT 包裹控制（上限一千行），落库存储的是这一千行内的同一份数据，历史回看与本轮看到的一致。

### 会话标题

首轮问题自动成为会话标题，后续可修改。

### 操作

支持关键词搜索、查看、删除与归档。归档是软删除，归档后的会话不出现在默认列表中，可按状态筛选查回。

会话与问答记录存在独立的会话库（读写连接），与只读的业务库分开，因此落库数据不受业务库只读约束影响，也不随 Checkpointer 配置变化。

Checkpointer 只保存图的中间状态，作用是同一会话内多轮之间的记忆延续。默认用 memory 时，进程重启后这部分中间状态丢失，但已落库的会话与问答记录仍在；需要跨重启保留图状态时，把配置切换到 sqlite。两者的持久化范围不同，不要混为一谈。

## 模块之间的数据流转

一次问答的最终返回包含六类信息：状态、结论与亮点、语句与改写前语句、口径与时间范围、图表配置、结果集与阶段列表。

前端按这六类分别渲染，不做二次加工。字段清单见《UIUX-界面设计文档》的契约一节。
