# 10 — API 密钥申请实训语料库

## 前置说明

本项目的模型网关走 OpenAI 兼容接口，凡是提供该兼容模式的服务商都可接入。切换服务商只需修改三项配置：接口地址、模型名、API Key，代码不需要改动。

以下流程以阿里云百炼（DashScope）为例。控制台的界面、菜单名称与模型列表以服务商最新官方文档为准，本文给出的是操作路径，不是一成不变的界面说明。

## 开通流程

### 第一步：注册与认证

访问阿里云百炼控制台，完成账号注册与实名认证。实名认证是使用模型服务的前置条件。

### 第二步：开通模型服务

进入模型服务相关页面，开通需要使用的模型。部分模型需要先申请开通，开通后才能调用。

### 第三步：创建密钥

在「API-KEY」或「密钥管理」页面点击创建新的密钥。

三点需要注意：

1. 密钥只在创建时完整显示一次，关闭弹窗后无法再次查看，只能重新创建；
2. 建议按用途分别创建，例如开发环境一个、演示环境一个；
3. 创建后立即复制保存，不要留在浏览器历史或聊天记录里。

### 第四步：确认接口地址与模型名

百炼的 OpenAI 兼容入口：

```
https://dashscope.aliyuncs.com/compatible-mode/v1
```

默认模型名 `qwen-plus`。可用的模型列表需查阅控制台，填错模型名会返回错误而不是自动纠正，这是调用失败时最先应该排查的一项。

## 配置到项目

### 复制配置模板

```bash
cd backend
cp .env.example .env      # Windows: Copy-Item .env.example .env
```

`.env.example` 由《开发任务文档》T6.3 产出。若仓库里还没有这个文件，按下面「填写内容」一节手动新建 `.env` 即可，配置项以 `app/config.py` 中的字段名为准。

### 填写内容

```ini
LLM_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
LLM_FALLBACK_MODEL=
LLM_TIMEOUT=30
LLM_MAX_RETRIES=2
```

| 配置项 | 说明 |
|---|---|
| `LLM_API_KEY` | 密钥，只在此处出现 |
| `LLM_BASE_URL` | OpenAI 兼容入口地址 |
| `LLM_MODEL` | 主模型名 |
| `LLM_FALLBACK_MODEL` | 备用模型，留空表示不启用降级 |
| `LLM_TIMEOUT` | 单调用超时秒数 |
| `LLM_MAX_RETRIES` | 单模型重试次数 |

`LLM_FALLBACK_MODEL` 仅在明确要启用降级时填写。主模型连续失败并耗尽重试后，会切换到该项配置的模型。

### 确认未被版本控制

`.env` 已在 `.gitignore` 中。提交前确认它不在待提交列表里，提交的是不含真实值的 `.env.example`。

## 验证配置

### 检查服务状态

```bash
curl http://127.0.0.1:8000/api/health
```

返回中 `llm_mock` 为 `false` 表示已使用真实模型；为 `true` 表示未读到有效密钥，当前走桩实现。

### 跑一次真实问答

```bash
curl -X POST http://127.0.0.1:8000/api/chat/sync \
  -H "Content-Type: application/json" \
  -d '{"session_id":"<会话ID>","question":"上个月各区域的成交总额"}'
```

判断配置是否生效的三个信号：结论不再是桩实现的固定话术；语句结构与语义层配置的口径一致；访问统计接口能看到调用记录。

### 查看用量

```bash
curl http://127.0.0.1:8000/api/stats
```

返回调用次数、失败次数、降级调用次数、输入输出 token 数与总耗时，并按节点标签分组。

## 无密钥时的行为

未配置密钥或密钥为空时，网关自动启用桩实现。桩按问题关键词返回预置内容，链路可以完整跑通，但结论与语句都是固定模板，**不能用来判断准确率**。

这个设计的目的是让开发在拿到密钥之前就能验证链路，不是让演示在无密钥状态下进行。评测集必须在配置真实密钥的环境下运行。

## 密钥管理

| 场景 | 做法 |
|---|---|
| 多环境 | 开发与演示使用不同密钥 |
| 团队协作 | 各自使用自己的密钥，不共享同一个 |
| 泄露处理 | 立即在控制台吊销并重新创建 |
| 定期轮换 | 演示结束后可吊销演示用密钥 |
| 提交前 | 确认 `.env` 未被纳入版本控制 |

## 配额与计费

计费方式与免费额度因服务商与模型而异，需查阅服务商当前文档。工程上能做的三件事：

1. 在控制台设置额度告警，避免演示期间意外消耗；
2. 网关记录用量，访问统计接口可随时查看；
3. 评测集运行前先估算条数与单条 token 消耗，避免一次跑几十条造成意外支出。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `llm_mock` 为 `true` | 密钥为空或 `.env` 位置不对 | 确认文件在 `backend/` 下且已填写，重启服务 |
| 认证失败 | 密钥错误或已吊销 | 检查控制台密钥状态，必要时重建 |
| 模型不存在 | 模型名与服务商命名不一致 | 查阅当前文档中的可用模型名 |
| 频繁超时 | 网络状况或服务端限流 | 调大超时并配置备用模型 |
| 限流错误 | 超出调用频率限制 | 重试机制会自动处理，仍频繁则需降低调用频率 |

重试只对超时、限流、连接类错误生效。参数错误（例如模型名写错、密钥错误）不会重试，因为重试多少次结果都一样。
