# 03 — 技术概念解释语料库

## FastAPI

Python 的 Web 框架，基于 Starlette 与 Pydantic。本项目用它实现接入层，负责 HTTP 路由、请求校验与 SSE 响应。

三个在本项目中实际用到的特性：

**类型注解即校验规则。** 请求体用 Pydantic 模型声明，字段约束写在类型上，框架在入口处完成校验，路由函数里拿到的已经是合法数据。

**依赖注入。** 通过 `Depends` 声明依赖，仓储、网关、图实例由容器统一提供，路由函数不负责创建。测试时替换依赖即可换掉真实实现。

**异步与流式响应。** 返回 `StreamingResponse` 即可实现 SSE，生成器每产出一帧就推送一帧。

## React 18

前端框架，组件化的核心是把界面拆成独立的、可复用的单元，每个单元只关心自己的状态与渲染。

本项目中的三个用法：

**Hook 封装副作用。** SSE 接收涉及连接建立、事件解析、连接关闭，属于典型的副作用场景，封装为 `useChatStream` 后组件只消费状态。

**受控输入与条件渲染。** 输入框在问答进行中禁用，结果区按状态渲染结论、图表或错误提示。

**组件目录按职责划分。** 对话面板、图表面板、SQL 面板、结果表格、阶段指示、口径标签各自独立，互不引用内部实现。

## TypeScript

给 JavaScript 加静态类型。本项目中的价值集中在接口契约：后端返回的字段结构用类型声明，字段名写错在编译期就能发现，而不是等到运行时拿到 `undefined`。

类型定义与后端的 Pydantic 模型逐项对应，是联调阶段减少低错误的第一步。

## Vite

前端构建工具，提供开发服务器与生产构建。开发阶段的代理配置把 `/api` 转发到后端，避免跨域问题；生产构建产出静态资源目录，交由 Nginx 提供。

## Ant Design

企业级 React 组件库。本项目用它的布局、输入、折叠面板、表格、标签与提示组件。使用组件库的意义不在外观统一，而在于交互细节（例如折叠动画、表格分页、提示的消失时机）不需要自己实现。

## ECharts

百度开源的图表库，通过配置对象描述图表。

本项目中的用法要点：

**配置由后端给出。** 图表类型与字段映射在 `visualize` 节点决定，前端拿到配置后渲染，不自行判断图型。

**渲染前校验字段。** 模型给出的配置可能引用结果集中不存在的列，直接渲染会得到空白图。前端核对配置引用的字段是否在结果集列名中，不通过则退回表格。

**容器需固定高度。** 容器高度为 0 时图表不显示，这是空白图最常见的原因之一。

## SQLAlchemy

Python 的 ORM 与数据库工具包。本项目只用它建立连接与执行原生语句，不做对象映射，因为查询由模型动态生成，无法预先定义映射关系。

用到的两点：`create_engine` 建立连接，`text()` 包装原生语句执行。会话记录表用 ORM 模型定义，因为它的结构是固定的。

## Pydantic

数据校验库，用类型注解声明数据结构。

本项目中的两处用途：一是 API 的请求与响应模型；二是模型结构化输出的契约，例如 SQL 草稿、图表配置、经营结论各定义一个模型，网关负责把模型输出解析并校验成这些结构。

解析失败时由网关重试，而不是把原始文本传下去。

## LangGraph

在 LangChain 之上构建状态机编排的库。核心概念是节点、边与状态。

**节点**是处理函数，接收状态返回状态的一部分更新。**边**决定流转方向，条件边按状态内容选择下一个节点。**状态**是节点之间唯一的数据契约。

本项目用它的三个能力：

1. 条件路由。校验失败与执行失败都能回到修正节点，修正后再回到校验，形成回环；
2. 状态归约。某些字段用追加语义的归约器，节点返回新增内容，框架负责合并；
3. Checkpointer。以会话 ID 为键持久化状态，实现多轮记忆。

需要注意的一点是：配置为追加归约的字段，在使用 Checkpointer 时会跨轮累积，因为 `operator.add` 的语义是旧值加新值，而 Checkpointer 保留了上一轮的终态。要限定为单轮语义，就得换归约器而不是换读取方式——接口层用 `stream_mode="updates"` 逐节点读取时，每个节点 update 里带回的字段值已经是归约后的全量，从第二个节点起就混入了上一轮内容。本项目的 `stages` 属于这类字段，它的语义被定义为单轮阶段列表，因此改用自定义归约器 `merge_stages`：入口节点 `route` 出现在本次更新中即丢弃历史值，其余情况正常追加。

与 Checkpointer 相关的另一处区分：它持久化的只是图的中间状态，用于同一会话内的多轮延续。已经落库的会话与问答记录存在独立的应用库中，不受 Checkpointer 配置影响——默认用 memory 时重启进程会丢掉图状态，但历史问答仍在。

## SSE

Server-Sent Events，服务端向浏览器单向推送的协议，基于 HTTP 长连接。

与 WebSocket 的区别：SSE 是单向的，浏览器原生支持，自动重连，实现成本低。本项目的场景是服务端推送进度与一次最终结果，没有客户端持续向服务端推消息的需求，因此 SSE 比 WebSocket 更合适。

帧格式：

```
event: stage
data: {"node":"generate","label":"正在生成查询",...}

```

每个事件以 `event:` 与 `data:` 两行构成，以空行结束。`data` 必须是单行 JSON，换行会破坏帧边界。

本项目定义四类事件：`stage` 节点进度、`result` 本轮结果、`error` 未预期异常、`done` 流结束。

## sqlglot

SQL 解析与转换库。本项目用它把语句解析成 AST，再做安全校验。

不用正则处理 SQL 的原因：正则无法可靠区分字符串字面量中的关键字与真实关键字，也无法处理嵌套结构。AST 校验能准确识别语句类型、表引用、字段引用与连接条件。

版本差异需要注意：不同版本中某些子句的存储形态会变化，遍历时应先判断类型再取内容，不要假定它一定是列表。
