# 04 — AI 共创开发流程语料库

## 什么是 AI 共创开发

AI 共创开发是指在产品研发过程中，借助大语言模型辅助完成需求文档、界面设计、代码开发与测试用例的编写，人负责提出约束、判断产出、承担责任。

它的价值不在于替代编码，而在于把重复性劳动交给模型，让人把精力放在判断上。本项目中，需求文档、界面设计文档、开发任务文档、造数脚本、节点实现、测试用例与交付文档都由人提出约束、模型产出初稿、人审查修正。

需要明确的是责任分配：模型负责产出，人负责判断。模型给出的内容看起来合理不等于正确，本项目已经出现过模型补全未给出的中间数值、生成与实际库不一致的字段名等情况。

## 共创的四个环节

| 环节 | 人做什么 | 模型做什么 |
|---|---|---|
| 提约束 | 给出背景、技术栈、运行形态、已有决策 | — |
| 出初稿 | — | 按结构产出文档或代码 |
| 做审查 | 逐条对照约束检查偏差 | — |
| 定取舍 | 判断哪些保留、哪些删掉 | — |

其中「提约束」决定了产出质量的上限。只说「帮我写一份 PRD」，得到的是通用模板；把技术栈、运行形态、目标用户、已有架构决策一起给进去，得到的才贴合项目。

## Prompt 设计方法

一个有效的提问结构包含四部分：

```
背景：<项目要解决什么问题，当前处于什么阶段>
约束：<技术栈 / 运行形态 / 目标用户 / 已有的架构决策 / 不做什么>
任务：<按什么结构产出什么>
要求：<可检验的约束，例如每条需求附验收方式>
```

四部分都不可省。缺背景，模型不知道轻重；缺约束，模型按常见形态生成；缺结构，产出的组织方式每次都不一样；缺要求，产出无法直接判断好坏。

**把不做什么写进去。** 这是最容易被忽略也最有效的一条。不加这条，模型会按通用 Web 应用的默认形态加入登录、权限、任务调度这些内容。

**给出真实的输入输出样例。** 让模型按契约写代码时，贴一段真实的响应 JSON，比描述字段名有效得多。

**要求给出判断依据。** 让模型在产出结论时说明依据，便于人审查时判断它是推理得来还是补全得来。

## 多轮对话优化

一次提问拿到满意结果的概率不高，多轮优化是常态。三种有效的追问方式：

**指出具体问题而非笼统不满。** 「字段编造的问题还在」比「写得不好」有效。

**给出反例。** 「问『退款率』时应该走 refunds 表，你给的是 orders 表」比「表选错了」有效。

**要求只改指定部分。** 「只改第三节，其余保持不变」可以避免模型顺手改动已经确认过的部分。

不推荐的追问方式是把整段重新生成。重新生成会丢失上一轮中正确的部分，也可能引入新的偏差。

## 产出物审查要点

### 文档类

| 检查项 | 判断标准 |
|---|---|
| 是否超出范围 | 对照「明确不做的事」，出现即删 |
| 是否可检验 | 每条需求与验收标准能否对应一个动作 |
| 是否自相矛盾 | 与已有文档交叉核对，尤其是字段名与接口名 |
| 是否有臆造内容 | 出现的接口、配置项能否在代码中找到 |

### 代码类

| 检查项 | 判断标准 |
|---|---|
| 是否满足分层约束 | 是否在不该出现的位置引入了不该有的依赖 |
| 是否处理异常分支 | 只有成功路径的代码在真实环境下会出问题 |
| 是否可单独测试 | 依赖是否通过参数注入而非内部创建 |
| 是否含硬编码 | 配置、路径、密钥是否都走了配置读取 |

### 数据类

这是最容易出问题的一类。用 AI 生成含数据的文档时，未在提示词中给出的中间数值会被模型自行补全，而且补出来的数字看起来都很合理。

规则是：交付前逐页核对数据页，把实测值与推测值分开标注，宁可去掉图表也不留未经验证的数字。

## 常见偏差与处理

| 偏差类型 | 典型表现 | 处理方式 |
|---|---|---|
| 范围膨胀 | 加入鉴权、调度、多租户 | 与「不做的事」对照删除 |
| 臆造能力 | 写上实时同步、自动归因 | 对照演进阶段，超出当前阶段的一律删 |
| 字段凭常识 | 写出库内不存在的字段名 | 以建表语句为准逐字核对 |
| 验收空泛 | 「响应迅速」「界面友好」 | 改成可数可测的表述 |
| 数据补全 | 给出未实测的耗时、准确率、样本数 | 标注为待核实，或删除 |
| 过度设计 | 引入项目不需要的中间件 | 对照 P0 阶段的「现在不做」清单 |

## 审查的两个通用动作

**动作一：定位落点。** 对文档中的每一条内容问「它的实现落在哪个模块」。答不上来的条目，要么是臆造，要么超出了当前形态。

**动作二：破坏性验证。** 写好测试或文档后，故意改坏一处，确认有测试失败或文档对不上。改坏了却一切正常，说明没有真正锁住行为。
