# 实训 6 — AI 共创：前端开发

## 一、实训目标

1. 搭建 React 18 + TypeScript + Vite + Ant Design 的前端工程
2. 封装 SSE 接收 Hook，把四类事件映射为界面状态
3. 封装 ECharts 组件，在渲染前校验图表配置引用的字段是否存在
4. 实现三区布局与助手回答卡片的固定结构
5. 让等待过程可感知，阶段进度逐条显示

## 二、前置条件

| 项 | 要求 |
|---|---|
| 前置产出 | 实训 5 的后端接口可用；实训 2 的界面设计文档 |
| 环境 | Node.js 20.19+ 或 22+，包管理器任选 |
| 联调 | `vite.config.ts` 中配置 `/api` 代理到后端端口 |

## 三、知识点

| 知识点 | 说明 |
|---|---|
| SSE 客户端 | 对话接口是 POST，原生 `EventSource` 发不出请求体，需要用 `fetch-event-source` 或 `fetch` + 流解析替代；在 React 中封装为 Hook 管理生命周期 |
| 事件驱动渲染 | 四类事件分别对应追加进度、渲染结果、展示错误、关闭连接 |
| 图表字段校验 | 模型给出的配置可能引用不存在的列，渲染前必须核对 |
| 类型对齐 | TypeScript 类型与后端 Pydantic 模型保持一致 |
| 前端无业务判断 | 图表类型与口径由后端决定，前端只做展示与校验 |

## 四、操作步骤

### 步骤 1：初始化工程

用 Vite 创建 React + TypeScript 工程，安装 Ant Design 与 ECharts。

```bash
npm create vite@latest frontend -- --template react-ts
cd frontend
npm install antd echarts axios @microsoft/fetch-event-source
```

`@microsoft/fetch-event-source` 用于接收 SSE，见步骤 4 的说明，不能用原生 `EventSource` 替代。

配置 `vite.config.ts` 中的代理，把 `/api` 转发到后端。

**预期输出**：`npm run dev` 后开发服务器可访问，代理转发正常。

### 步骤 2：定义类型

`api/types.ts` 中定义与后端响应对齐的类型：阶段事件、结论、口径标签、图表配置、结果集与状态。

类型字段与后端 `result` 事件的返回逐项对应，其中 `status` 的取值是四个：`ok`、`clarify`、`chitchat`、`error`。字段不一致是联调阶段最常见的问题来源。

**预期输出**：类型文件覆盖后端返回的全部字段，四个 `status` 取值都有对应的界面分支。

### 步骤 3：封装 HTTP 客户端

`api/client.ts` 创建 axios 实例，统一处理错误提示。

**预期输出**：请求失败时有全局提示，不静默。

### 步骤 4：实现 SSE Hook

`hooks/useChatStream.ts` 是本次实训的核心。职责为：发起请求、解析 `stage` / `result` / `error` / `done` 四类事件、维护阶段列表与结果、在 `done` 或 `error` 时关闭连接。

**为什么不用原生 `EventSource`**：`EventSource` 只能发 GET 请求，而对话接口 `POST /api/chat` 需要携带 `session_id` 与问题文本的请求体，因此原生 API 用不了。两种可行做法：

- 用 `@microsoft/fetch-event-source`。它基于 `fetch`，支持 POST 与自定义请求头，并自动重连，与本实训的接口形态最匹配；
- 用 `fetch` 配合 `response.body.getReader()` 自己解析字节流，按空行切分事件。不引入额外依赖，但要自己处理跨 chunk 的半包与编码问题。

axios 在这里也不适用：浏览器端 axios 基于 XMLHttpRequest，读不到流式响应体，只能等响应结束后拿到完整文本，阶段事件会一次性出现。

注意三点：阶段事件按到达顺序追加，不重排；连接关闭要放在 `finally` 逻辑里，避免异常时泄漏；每一轮问答持有自己的阶段列表，不需要在发出新问题时清空上一轮的内容。

最后一点的依据在服务端的修法，而不是前端的约定。`stages` 曾出现跨轮累积：第二轮显示 14 个阶段、第三轮 21 个。根因在状态归约层——`operator.add` 的语义是旧值加新值，而 Checkpointer 保留了上一轮的终态。现已改用自定义归约器 `merge_stages`，以入口节点 `route` 是否出现在本次更新中作为新一轮的判定依据（节点名提取为 `ENTRY_NODE` 常量，图装配与归约判断共用），出现则丢弃历史值。因此接口返回的 `stages` 已经是本轮内容，前端按轮次分别存放即可。

**预期输出**：问答过程中阶段逐条出现，结束后连接关闭。

### 步骤 5：实现对话页与阶段指示

`pages/ChatPage.tsx` 实现三区布局。`components/StageIndicator/` 按阶段事件显示标签与耗时，完成后收起为一行。

节点名到展示文案的映射按界面设计文档的表格实现，覆盖十一个节点：八个业务节点加 `respond`、`clarify`、`give_up` 三个终态节点。终态节点同样推送 `stage` 事件，映射表里漏掉 `respond` 会让闲聊类问答的最后一个阶段显示为原始节点名。

**预期输出**：等待期间能看到「正在生成查询」这类提示。

### 步骤 6：封装图表组件

`components/ChartPanel/` 接收后端给出的图表配置。渲染前校验配置引用的字段是否存在于结果集列名中，不通过则退回表格展示。

这一条不能省。模型输出的字段映射可能引用不存在的列，直接渲染会得到一张空白图，用户无法判断是没数据还是画错了。

**预期输出**：构造引用不存在字段的配置时，界面展示表格而不是空白图。

### 步骤 7：实现 SQL 面板与结果表格

`components/SqlPanel/` 用折叠面板展示实际执行的语句；存在改写时同时展示改写前的语句。`components/ResultTable/` 展示结果集，超过 50 行分页，列名直接取结果集列名。

**预期输出**：展开面板能看到完整语句，宽表可横向滚动。

### 步骤 8：实现口径标签与结论卡片

`components/MetricBadge/` 展示本轮采用的指标与边界说明，内容取自返回的 `metric_used` 与 `caveats`。

**预期输出**：每轮回答下方能看到口径标签。

### 步骤 9：实现历史会话页

`pages/HistoryPage.tsx` 展示会话列表，支持关键词搜索、查看、删除与归档。

归档调用 `PATCH /api/session/{id}` 提交 `{"archived": true}`，是软删除：归档后会话不再出现在默认列表中，通过状态筛选「已归档」可以找回，记录本身不删除。

**预期输出**：操作后列表同步更新；归档的会话在默认列表消失、在已归档筛选下仍在。

### 步骤 10：联调验证

在浏览器中完成一次完整问答，检查阶段提示、图表、SQL 面板、结果表格与口径标签五项是否都正常。

**预期输出**：一次问答的全部产出都能在界面上看到。

## 五、AI 共创要点

**怎么问**：给出后端返回的字段结构，让 AI 按契约生成组件。只说「写一个图表组件」，AI 会自行假设数据结构，接上真实接口才发现字段名对不上。

一个可用的提问结构：

```
后端返回：<贴一段真实的响应 JSON>
任务：实现 <组件名>
约束：
1. 图表配置中的字段需校验是否存在于 columns 中，不存在则退回表格
2. 不做任何业务判断，只做展示
3. 空数据与超长标签要处理
```

**常见偏差**：

| 偏差 | 表现 | 处理 |
|---|---|---|
| 字段名靠猜 | 用 `data.rows` 而实际是 `rows` | 贴真实响应，让 AI 按契约写 |
| 图表直接渲染 | 不校验字段，空白图 | 加渲染前校验与表格兜底 |
| 前端决定图表类型 | 按行数自己选折线或柱状 | 移回后端，前端只展示 |
| SSE 连接不关闭 | 每次问答泄漏一个连接 | 在 `done` 与异常分支都关闭 |
| 等待期无反馈 | 只有转圈 | 接入阶段事件，逐条显示 |
| 金额用红绿区分 | 增长标红下降标绿 | 改为统一中性色 |

**审查动作**：在组件代码中搜索 `if` 判断。出现的判断应该只与展示形态有关，例如是否截断、是否分页、是否退回表格。出现与业务口径有关的判断，说明职责越界。

## 八、常见问题

**问题：开发服务器能起来，但请求 404。**
原因：代理未生效或前缀写错。解决：检查 `vite.config.ts` 中的代理前缀与后端路由前缀是否一致，后端路由前缀为 `/api`。

**问题：阶段事件一次性全部出现。**
原因：经过 Nginx 或代理层时响应被缓冲。解决：后端响应头已设置 `X-Accel-Buffering: no`，若走 Nginx 还需在配置中关闭缓冲。

**问题：图表区域空白但结果表格有数据。**
原因：图表配置引用了不存在的字段，或容器高度为 0。解决：核对字段校验逻辑，并给容器设置固定高度。

**问题：页面报错后 SSE 连接未关闭，重复提交后连接数累积。**
原因：异常分支没有关闭连接。解决：在 `finally` 中统一关闭，并在组件卸载时也关闭。
