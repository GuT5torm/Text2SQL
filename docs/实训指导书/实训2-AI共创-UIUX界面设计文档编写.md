# 实训 2 — AI 共创：UI/UX 界面设计文档编写

## 一、实训目标

1. 针对「一次问答要等数秒到十几秒」这个特点，设计出让等待可感知的界面
2. 写出一份含信息架构、布局规范、组件清单、状态设计、视觉规范的界面设计文档
3. 定义前端与后端的数据契约，明确哪些判断由后端做、前端只做展示
4. 用 AI 辅助生成布局与配色方案，并能识别出不适合本项目的通用建议

## 二、前置条件

| 项 | 要求 |
|---|---|
| 输入材料 | 《PRD-产品需求规格说明书.md》《Text2SQL-Agent-系统架构设计.md》第 8 节 |
| 环境 | 无特殊要求 |
| 知识 | 了解 React 组件划分与 ECharts 的基本配置结构 |

## 三、知识点

| 知识点 | 说明 |
|---|---|
| 流式进度反馈 | 一次问答跨越八个节点，等待期间必须有阶段提示 |
| SSE 事件驱动渲染 | 前端按 `stage` / `result` / `error` / `done` 四类事件更新界面 |
| 结果可追溯 | SQL 与口径标签的位置要在两跳之内可达 |
| 失败态设计 | 拦截、重试、重试耗尽、空结果、断连五种异常各有文案与引导 |
| 渲染前字段校验 | 模型给出的图表配置可能引用不存在的字段，前端必须校验 |

## 四、操作步骤

### 步骤 1：确定设计目标

写四条目标并给出衡量方式，其中「等待可感知」与「结果可追溯」是本项目的重点。

**预期输出**：四行表格，含目标与衡量方式两列。

### 步骤 2：画信息架构

用树形结构列出主页面与历史页的组成，标注每个区域的职责。

**预期输出**：ASCII 树，主页面下含顶部栏、对话区、结果区，结果区下含结论卡片、图表区、SQL 面板、结果表格。

### 步骤 3：定布局与响应式规则

左侧对话区 380 到 480px 可拖拽，最小 320px；右侧结果区自适应，最小 640px；区域间距 16px，卡片间距 12px。窗口宽度小于 1024px 时改为上下堆叠。

**预期输出**：尺寸表与响应式说明各一段。

### 步骤 4：确定助手回答卡片的固定结构

顺序为：阶段指示、结论文本与亮点、口径标签、图表区、SQL 折叠面板、结果表格。顺序不可调换，理由是用户先看结论再看依据。

**预期输出**：一段 ASCII 框图示意。

### 步骤 5：列组件清单

七个组件：`StageIndicator`、`ChatPanel`、`ChartPanel`、`SqlPanel`、`ResultTable`、`MetricBadge`、`useChatStream`。每个写清职责与关键约束。

约束要具体。例如 `useChatStream` 的约束是「解析四类事件，`done` 时关闭连接」，`ChartPanel` 的约束是「渲染前校验字段存在于结果集列，否则退回表格」。

**预期输出**：七行表格。

### 步骤 6：设计状态与异常

问答主流程五个步骤的状态变化写成表；阶段文案写成节点名到展示文案的映射表；五种异常态各写表现与引导。

**预期输出**：三张表格。

### 步骤 7：定视觉规范

配色、字体、圆角、图表规范四小节。图表规范要写明高度固定 320px、标题不显示在图表内、金额显示千分位与两位小数。

特别说明一条：金额与涨跌不使用红绿语义色。本项目是经营数据分析不是行情看板，避免与股票涨跌的配色惯例混淆。

**预期输出**：四张规范表。

### 步骤 8：定义前后端契约

列出前端直接消费的字段与用途，并写明前端不做业务判断。

**预期输出**：字段用途表。

## 五、AI 共创要点

**怎么问**：把「等待时长」这个约束明确给 AI。如果只说「设计一个数据分析对话界面」，AI 会给出常见的聊天界面方案，这类方案默认响应是几百毫秒，不会考虑阶段进度。

一个可用的提问结构：

```
场景：一次问答要等数秒到十几秒，中间经过八个处理节点
约束：前端只做展示，不做业务判断；图表配置由后端给出
任务：设计 <信息架构 / 布局 / 组件清单 / 状态与异常 / 视觉规范>
要求：异常态要覆盖拦截、重试、重试耗尽、空结果、断连五种
```

**常见偏差**：

| 偏差 | 表现 | 处理 |
|---|---|---|
| 只设计成功态 | 没有拦截、重试、空结果的界面 | 补齐五种异常态 |
| 引入鉴权界面 | 登录、注册、角色管理 | 本项目单用户本地运行，删掉 |
| 配色用红绿表示涨跌 | 金额增长标红、下降标绿 | 改为统一中性色，说明原因 |
| 组件职责含业务判断 | 让前端决定图表类型 | 移回后端，前端只做字段校验 |
| 图表交互过度 | 联动、下钻、刷选 | 保留基本悬浮提示即可 |

**审查动作**：对照「前端不做任何业务判断」这一条，逐个组件检查职责描述。出现「决定」「判断」「计算」这类动词的地方都要改。

## 八、常见问题

**问题：AI 给出的界面方案包含登录与用户管理。**
原因：AI 按通用 Web 应用的默认形态生成。解决：在提问中写明「本地单机单用户，无鉴权」，并在审查时对照 PRD 的「明确不做的事」。

**问题：阶段文案和后端节点名对不上。**
原因：设计文档写好后后端节点改名。解决：以 `agent/nodes/` 下的文件名为准，映射表在联调阶段复核一次。

**问题：图表区高度随内容变化导致布局跳动。**
原因：ECharts 容器没有固定高度。解决：容器固定 320px，空数据时不渲染图表改渲染表格。
