# 附录 A — 申请 LLM API 密钥

> 适用：《实训5-AI共创-后端开发》第 1 步
> 说明：以下流程与配置项以服务商最新官方文档为准，界面与菜单名称可能调整

---

## 一、选择服务商

本项目的 LLM 网关走 OpenAI 兼容接口，凡是提供该兼容模式的服务商都可接入，切换只需修改 `.env` 中的三项配置：接口地址、模型名、API Key。

本项目默认使用阿里云百炼（DashScope），理由是它提供 OpenAI 兼容入口，且国内可直连。若你有其他服务商的可用密钥，直接替换配置即可，代码无需改动。

以下服务商均提供 OpenAI 兼容模式，具体模型名称、接口地址与计费方式需查阅各家最新文档：阿里云百炼、DeepSeek、智谱 GLM、月之暗面 Kimi、火山方舟、硅基流动。

---

## 二、开通与获取密钥

### 2.1 开通服务

1. 访问阿里云百炼控制台，完成账号注册与实名认证；
2. 进入模型服务页面，开通需要使用的模型服务；
3. 在左侧菜单进入「API-KEY」或「密钥管理」页面。

页面名称与入口位置以控制台当前版本为准。

### 2.2 创建密钥

1. 点击「创建新的 API-KEY」；
2. 记录生成的密钥字符串。密钥只在创建时完整显示一次，关闭弹窗后无法再次查看，只能重新创建；
3. 建议按用途分别创建密钥，例如开发环境一个、演示环境一个，便于出现泄露时单独吊销。

### 2.3 获取接口地址

百炼的 OpenAI 兼容入口地址为：

```
https://dashscope.aliyuncs.com/compatible-mode/v1
```

模型名填 `qwen-plus`。可选的备用模型需查阅控制台中当前可调用的模型列表，填错模型名会返回错误而不是自动纠正。

---

## 三、配置到项目

### 3.1 创建配置文件

在 `backend/` 目录下复制配置模板：

```bash
cd backend
cp .env.example .env
```

配置模板由《开发任务文档》T6.3 产出。若此时该文件尚不存在，先按下面 3.2 的字段自己新建，字段缺一项会走默认值而不是报错。

### 3.2 填写内容

```ini
LLM_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
LLM_FALLBACK_MODEL=
LLM_TIMEOUT=30
LLM_MAX_RETRIES=2
```

`LLM_FALLBACK_MODEL` 留空表示不启用降级。主模型连续失败时会切换到该项配置的模型，仅在明确要启用时填写。

### 3.3 确认读取位置

密钥只出现在 `.env` 中。代码通过 `config.py` 读取，任何源文件中都不应出现密钥字面量。项目结构中已把 `.env` 加入 `.gitignore`，提交前确认该文件未被纳入版本控制。

## 四、验证配置

### 4.1 检查服务状态

启动后端后访问健康检查接口：

```bash
curl http://127.0.0.1:8000/api/health
```

返回中 `llm_mock` 为 `false` 表示已使用真实模型；为 `true` 表示未读到有效密钥，当前走的是桩实现。

### 4.2 跑一次真实问答

对话接口要求会话已存在，先创建会话并记下返回的 `id`：

```bash
curl -X POST http://127.0.0.1:8000/api/session \
  -H "Content-Type: application/json" \
  -d '{"title":"密钥验证"}'
```

再发一个问题：

```bash
curl -X POST http://127.0.0.1:8000/api/chat/sync \
  -H "Content-Type: application/json" \
  -d '{"session_id":"<上一步返回的 id>","question":"上个月各区域的成交总额"}'
```

会话不存在时接口返回 404 并提示「会话不存在」，不会自动新建。

返回的 `answer` 不再是桩实现的固定话术，且 `sql` 由模型生成，说明配置生效。

### 4.3 查看用量

访问统计接口查看调用次数与 token 用量：

```bash
curl http://127.0.0.1:8000/api/stats
```

## 五、安全配置

| 项 | 做法 | 原因 |
|---|---|---|
| 密钥位置 | 只放在 `.env` | 硬编码进代码会被提交到仓库 |
| 版本控制 | `.env` 加入 `.gitignore` | 避免误提交 |
| 提交前检查 | 检查 `.env` 是否在待提交列表中 | 模板文件是 `.env.example`，不含真实值 |
| 分环境密钥 | 开发与演示使用不同密钥 | 泄露时可单独吊销，不影响其他环境 |
| 泄露处理 | 立即在控制台吊销并重新创建 | 吊销后旧密钥立即失效 |
| 配额 | 在控制台设置额度告警 | 避免演示期间意外消耗 |

## 六、常见问题

**问题：健康检查返回 `llm_mock: true`。**
原因：`LLM_API_KEY` 为空，或 `.env` 文件位置不对。解决：确认 `.env` 位于 `backend/` 目录下，且密钥项已填写；修改后重启服务。

**问题：调用返回认证失败。**
原因：密钥错误或已吊销。解决：在控制台检查密钥状态，必要时重新创建并更新 `.env`。

**问题：返回模型不存在。**
原因：模型名与该服务商的命名不一致。解决：查阅服务商当前文档中可用的模型名，不同服务商的同一个模型可能有不同别名。

**问题：调用频繁超时。**
原因：网络状况或服务端限流。解决：适当调大 `LLM_TIMEOUT`，并配置 `LLM_FALLBACK_MODEL` 启用降级。注意重试只对超时、限流、连接类错误生效，参数错误不会重试。
